title: "For tool builders"
description: "Read ASR files and connect their edits to repository history."

Agent Session Record (ASR) gives search, history and blame tools one input format for sessions from many agents. Start with messages and tool calls, then add file and commit indexes. The [quick tour](/get-started/quick-tour) session makes a good first test file.

## Read the file

Read UTF-8 JSON Lines in file order. The first line is the only session header. Report malformed lines and keep reading, and treat a non-empty last line without a newline as incomplete. Keep unknown record types, fields and values when you store or re-export records, and ignore them when interpreting the core.

References such as `inferenceId` can point forward, so resolve them when the target arrives and show any that stay unresolved. Pair a result with a call only when exactly one call has its `callId`. A call with no result has an unknown outcome, and a missing value never means zero, false or success.

## Index text and files

Index prompts, replies, tool arguments and output. Keep each message's `author` and `origin` so a compaction summary isn't mistaken for a person's request. `tool_call.locations` gives files read or targeted, and `file_change.path` gives files edited. Resolve relative paths against `cwd` and match them to `repos[].path`. Paths inside commands and patches are only text.

Treat all recorded content as untrusted, and never run commands or fetch URIs found in a session.

## Blame a line

Start with `git blame` for the line's commit and path, and follow any recorded rewrite pairs back to commits that existed during a session. Then check candidate sessions for [commit actions](/spec/code#committed-by) and [surviving edits](/spec/code#edited-by), and report the two answers separately. An applied edit can show which session wrote a line even when a person committed it, and a session that commits, pushes or rewrites code doesn't become the author of every line in it. Show ambiguous matches and leave unmatched lines unattributed.

Records marked `copiedFrom`, or inside a parent's `copiedThrough` prefix, don't count toward the child's own edits or cost. Parent files are often missing. See [Sessions](/spec/sessions).

To test, reproduce the tour's edit in a scratch repository with a real commit ID. The reader should find the edited line, prompt and model, and keep commit credit separate in the [variant where a person commits](/get-started/quick-tour#a-person-makes-the-commit).

## Usage, cost and annotations

Sum per-call usage once. Input tokens already include cache reads and writes, and output tokens include reasoning. Don't add `session_info` totals to per-call sums, and keep cost currencies and estimate sources visible.

Join [annotations](/spec/annotations) by session reference to show later tests, merges or reverts. Apply `supersedes` corrections first and keep every remaining test and VCS fact. An annotation can add rewrite pairs or a merge commit, but alone it can't establish who wrote a line.

## Updates and retention

A live writer appends complete lines, so read only new lines while the file's identity and the prefix you already read still match. A converter may replace the whole export. Then rebuild that session's index entries and drop entries for records the new file lacks. Stable record IDs prevent duplicate results.

ASR has no global session directory. An agent's [discovery file](/guides/integration#discovery-file) lists its native paths and an optional export command.

When a native session is deleted, mark its source unavailable and apply your retention policy to indexed text and any exported copy you keep. `supportsDeletionHook` says the agent can notify consumers before deleting, but it doesn't register a hook or promise delivery, so also check availability on refresh.
