ASR is an open specification maintained in its [public repository](https://github.com/agentsessionrecord/asr). Wills Manley maintains it. Issues and pull requests are the place to propose changes and review their effect on producers and readers.

## What belongs in the core

A feature belongs in the core when it helps answer the questions in the [overview](/spec/overview) and is cheap for a converter or agent to produce.

A proposal should show both sides. It should identify a useful reader question and native data that can answer it without guessing. Review considers the implementation cost, behavior with missing data, and whether readers can interpret the result consistently.

## Guides and agent notes

Guides add no requirements. They explain how ASR connects to other tools. Converter notes describe particular source versions and their limits. Adding an agent to the list reserves a short name. It does not certify a converter or claim that every version is supported.

Corrections to those pages can be made without changing `formatVersion`. Native facts need a source or a sample that supports the mapping.

## Extensions and compatibility

Vendor data uses `_meta` and namespaced record types. Named extensions can add records and fields while preserving core meanings. Readers can ignore an extension and still interpret the core. Storage tools preserve unknown data.

Core changes are reviewed together with schemas, examples and validation behavior. A shared shape is added once at least two of Claude Code, Codex and OpenClaw record the same fact. Version decisions consider what writers produce and what readers can understand.

## Stability during 0.1

Agent makers can build on version 0.1 now. The [Versions section](/spec/format#versions) defines stable requirement IDs and meanings, optional additions and a new format version for breaking changes. Readers ignore unfamiliar data and storage tools keep it. The tools in this repository keep reading 0.1 files.

Send feedback through [issues](https://github.com/agentsessionrecord/asr/issues) and [pull requests](https://github.com/agentsessionrecord/asr/pulls).
