## Does an agent harness have to store its sessions in ASR?

No, but it can. ASR is an export format first: a harness, the app such as Claude Code or Codex, can keep its own log format and add a command that writes ASR. ASR also works as a harness's own log. It's written a line at a time, and anything app-specific can go in each record's `_meta`. Harnesses without an export command can still be read by the ASR converters.

## Why JSON Lines and not SQLite or Parquet?

ASR is built to be easy to write, read and keep, not to be fast to query.

A session is a mix of record types in order: prompts, model calls, tool calls, file edits and commits, each with different fields. JSON Lines keeps them as one ordered stream. Parquet wants one fixed set of columns per table, so a session would be split across tables or carry mostly empty columns.

A JSON Lines file can be written and read one line at a time, so a long session with large tool output never has to be loaded whole. Every language can read it, and a person can open it and see what happened, which matters for audits. New fields and agent-specific data can be added, and older readers skip what they don't know. Recorders that write while a session runs can append to it, and every complete line survives a crash.

SQLite and Parquet are better for querying many sessions at once. The [tables exporter](https://github.com/agentsessionrecord/asr/blob/main/exporters/tables/) turns ASR files into Parquet tables you can load into DuckDB. Some agents, such as opencode and Goose, store sessions in SQLite, and the converters read those databases directly.

## How does ASR relate to ACP, Git AI, OpenTelemetry and Git?

| Tool or format | What it covers | What it leaves out |
|---|---|---|
| [ACP](https://agentclientprotocol.com/) | Live communication between an editor and an agent | A record after the session. Most sessions run without it. |
| [Git AI](https://github.com/git-ai-project/git-ai) | Line attribution in Git notes | The prompt, model call and tool history behind a line |
| [OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/gen-ai/) | Monitoring model and tool operations | Retained content by default, and any model of files and commits |
| Git | File and commit history | Who edited a line before it was committed, and why |

A [recorder](/guides/acp) can save an ACP session as ASR, [Git AI notes](/guides/git-ai) can be written from ASR blame results, and model calls can be [exported to OpenTelemetry](/guides/otel).

## Can an agent ship version 0.1 now?

Yes. Changes to 0.1 only add optional fields, record types and enum values, and requirement IDs and meanings don't change within a format version. A breaking change gets a new `formatVersion`, and the tools in this repository keep reading 0.1 files. See [Versions](/spec/format#versions).

## Does a commit show who wrote a line?

No. One session can edit a file and another commit it, and a person can commit an agent's edits. So readers give two separate answers. Edited by needs an applied edit whose added lines survive in the commit, and committed by needs a recorded commit that passes the [repository checks](/spec/code#committed-by). A commit trailer or a commit mentioned in a reply only points to a candidate session, and even a match is evidence, not proof. The [quick tour](/get-started/quick-tour#a-person-makes-the-commit) shows a person committing an agent's edit.

After a rebase, recorded rewrite pairs connect the old and new commits. A squash commit can be checked directly against the surviving edit text. Similar commit subjects alone don't establish a rewrite.

## What if the source log is incomplete?

Unknown fields stay absent. The header lists known losses, a `gap` marks missing history and shortened text is marked `truncated`. A session without edit records can still be searched. See [Missing data](/spec/missing-data).

## Can I replay or resume a session?

ASR doesn't define resume or replay, and it doesn't reconstruct the exact request a model saw, because native state can hold model context or provider data that ASR doesn't keep. [Replaying sessions](/guides/replay) shows how recorded sessions can still be used to compare models and prompts.

## Is a valid file safe to share?

No. Prompts, paths and tool output can contain private information, and validation only checks structure. Producers exclude known secrets, redaction creates a new file, and readers treat all recorded content as untrusted.

## Where do test results learned later go?

In a separate [annotations file](/spec/annotations), along with later outcomes and summaries. It can change without touching the session file.

## Can I add my own fields?

Yes, in `_meta` under a reverse-DNS key. Agents can also add namespaced record types, and named extensions can add fields and records without changing what core records mean.

## Can a company collect sessions or use them for audits?

Yes. See [Running ASR across a company](/guides/organizations) and [Using ASR for audits](/guides/audits). A collected file shows only what the machine kept, and the person running the agent can change local logs before collection.
