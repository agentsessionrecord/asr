`asr collect` converts native sessions that changed and stores the exact Agent Session Record (ASR) files. `asr receive` accepts authenticated HTTP uploads. Both come with the [CLI](/tools).

| Tool README | Live-test status |
| --- | --- |

| [ASR session collector](https://github.com/agentsessionrecord/asr/blob/main/crates/asr-collect/README.md) | `partial` |

```sh
asr collect --source codex=./native-history \
  --target ./received --state ./collector-state --uploader configured-account
```

Add `--watch` to scan on file events, with periodic recovery scans. `--source` limits discovery to the sources you name. Keep state and output outside the native source directory.

## Storage and receipts

Sessions can go to local directories, the reference HTTP receiver, or S3-compatible, GCS and Azure storage. The receiver's private authentication file ties each token to an uploader and the machines it may upload from. Remote HTTP collection needs TLS through a proxy you run.

Receipt manifests identify the exact bytes received and link to earlier manifests. Re-exports keep earlier versions. A receipt does not show that capture was complete or who wrote a session.

## Test results

Local watch, polling and receiver checks passed, and a local MinIO container verified multipart uploads, exact bytes and digests. Production S3, GCS and Azure were not tested.
