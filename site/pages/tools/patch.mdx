Each package contains local source patches and a proposal. Nothing in this
catalog implies an upstream release or an accepted patch. Choose the exact
source base in the package's manifest and use a separate writable checkout.

Each README gives installation, native export usage, recorded facts, losses and
test evidence. Package checks validate digests, patch syntax, synthetic source
contracts and ASR samples. The reproduction command replays the ordered series
through a temporary Git index. It does not build the upstream agent or run a
model session.

Test status comes from the [repository registry](https://github.com/agentsessionrecord/asr/blob/main/registry.json).
`passed` names a tested path. `partial` means only part of the host path ran.
`not-live-tested` means no qualifying host or service run is recorded.
`not-applicable` applies to offline tools and shared libraries.
Read each README for the version, test scope and remaining limits.

## Capture and host limits

Most packages add offline export of retained native history. Grok Build adds
an opt-in event sidecar. OpenHands and Roo Code add export choices in their
existing interfaces. Other packages expose CLI commands, examples or an
authenticated route. Read the selected package's usage before applying it.

Stored history can lack approval decisions, final model inputs, usage, file
changes, commits or session relationships. The patch preserves supported facts
and declares known losses. A valid export does not establish complete capture.

Gemini CLI, Qwen Code, OpenClaw, Continue and OpenHands have `partial` status for
limited host paths. Their READMEs state which command, export function or SDK
boundary ran. Zed retains an upstream human review marker. The package check
does not remove that requirement. Review and build an upstream candidate using
its own instructions before using the patch beyond its tested scope.
