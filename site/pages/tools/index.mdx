Install the Agent Session Record (ASR) tools from a checkout of the [repository](https://github.com/agentsessionrecord/asr). None is published as a package or service. Each tool's README covers setup, limits and test results.

| Job | Use it for |
| --- | --- |
| [Convert](/tools/convert) | Turn native agent logs and databases into ASR. |
| [Record](/tools/record) | Capture new sessions through agent hooks, model gateways or ACP. |
| [Collect](/tools/collect) | Find changed sessions and store exact copies with receipts. |
| [View](/tools/view) | Read a session timeline or find the session behind a Git line. |
| [Export](/tools/export) | Turn ASR into traces, tables, search indexes, eval datasets and Git notes. |
| [Import](/tools/import) | Turn vendor exports and checkpoint stores into ASR. |
| [Patch](/tools/patch) | Add ASR export to an agent's own source. |

## Install the CLI

You need Rust, Git, Node.js 22.13 or later and pnpm 12.11.2. From the repository root:

```sh
pnpm --filter @agent-session/validate install --frozen-lockfile
cargo install --path crates/asr-cli --locked
asr agents
```

Keep the checkout and set `ASR_REPO_ROOT` to its absolute path when you run `asr` from another directory. The viewer, exporters, importers and plugins have their own entry points.

## Validate, redact, blame and replay

`asr validate` checks file structure and the links between records, and `asr redact` writes a redacted copy. Neither makes a file safe to share. `asr blame` finds the session text behind a Git line and reports it apart from the commit. `asr replay` resends one model request with your private provider settings and writes the answer as a fork session, without running any tool calls.

A blame match means the committed line equals text the session wrote in the checked time window. It does not show who typed the line. A person who typed the same text, such as shared boilerplate, looks the same.

Read the [security and privacy guidance](https://github.com/agentsessionrecord/asr/blob/main/SECURITY.md) before you capture, import, store or share sessions.

## Live-test status

Each status comes from the [repository registry](https://github.com/agentsessionrecord/asr/blob/main/registry.json). `passed` means a live run passed on the path the README names. `partial` means only part of the host path ran. `not-live-tested` means no qualifying run against the real host or service is recorded. `not-applicable` covers offline tools and shared libraries. Some tools passed a host run before later changes that were only tested against fixtures.
